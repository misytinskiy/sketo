# Казахский перевод

В Supabase → SQL Editor выполните два файла **отдельными запусками**, в таком порядке:

1. `migrations/20260924010000_kazakh_locale.sql` — добавляет `kz` в enum `public.locale`.
2. `migrations/20260924020000_kazakh_catalog.sql` — добавляет переводы 8 локальных лотов кофе и 6 моделей оборудования, включая характеристики и особенности.

Сначала примените SQL, затем разверните обновлённый сайт. В PostgreSQL новый enum должен быть зафиксирован до использования. При работе через Supabase CLI миграции также должны выполняться отдельными транзакциями.

Скрипт сопоставляет товары по `slug` и типу. Он не создаёт товары, не меняет RU/EN и не перезаписывает существующие KZ-переводы. Повторный запуск безопасен. Если локальные описания уже менялись в базе, проверьте добавленный KZ в стаф-панели перед публикацией сайта.

Товары, которые существуют только в базе, переводятся через **Staff → Редактировать → Версия на казахском**. Пока строки KZ нет, сайт показывает русскую версию товара. При сохранении доступны название, описание, ноты и размер кофе, категория оборудования, детали, особенности и спецификации. Общие поля товара остаются общими для языков.

Публичный каталог кэшируется до 5 минут; после SQL новый перевод появится при обновлении кэша или после развёртывания новой версии. Сохранение в стаф-панели сбрасывает кэш сразу.

Код языка в интерфейсе, cookie и базе — `kz`; в HTML `lang` используется стандартный код казахского `kk`.

Если локальные переводы каталога изменились, пересоздайте SQL: `node scripts/generate-kazakh-sql.mjs`. Генератор работает только с файлами и не подключается к базе.
