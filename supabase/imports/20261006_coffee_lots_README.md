# Импорт кофе из скриншотов

Файл: `20261006_coffee_lots.sql`. Это готовый SQL-скрипт для существующей базы Sketo, не SQL-инъекция. Рабочая база при подготовке файла не изменялась.

## Запуск

1. Откройте нужный проект Supabase → **SQL Editor → New query**.
2. Вставьте **весь** SQL-файл и нажмите **Run**. Импорт выполняется одной транзакцией: ошибка отменяет его изменения целиком.
3. Посмотрите таблицу результатов: создан ли черновик или найдена существующая карточка, ссылка на редактор и замечания по данным.
4. Обновите `/staff`. Для просмотра заданного порядка выберите сортировку **«По статусу»**: внутри одного статуса учитывается порядок импорта. «По названию» по-прежнему сортирует по алфавиту.
5. Добавьте фото, проверьте наличие, недостающие поля и тексты на трёх языках, затем опубликуйте новые карточки.

Новые карточки создаются **черновиками** с заглушкой фотографии и предварительным статусом **«В наличии»**, как при обычном добавлении товара через кабинет. Это значение нужно проверить: скриншоты не подтверждают фактические остатки. Скрипт не публикует новые товары автоматически.

Подготовлены **RU / EN / KZ**: названия, краткие описания, вкусовые ноты, фасовки, подписи и значения характеристик. Собственные названия брендов, ферм и лотов при необходимости сохранены в оригинале. SEO-поля оставлены для автоматического формирования из локализованного названия и краткого описания.

**Если предыдущий русский импорт уже выполнен, запустите обновлённый SQL целиком ещё раз.** Он добавит отсутствующие языковые версии с характеристиками. Уже существующие версии, даже пустые, сохраняются: их нужно проверить в кабинете. Если у локали уже были отдельно заполнены характеристики, они также сохраняются. Фотографии, цены и русские правки не перезаписываются.

Схема должна поддерживать локаль `kz`, как текущий сайт. Если скрипт сообщает об её отсутствии, сначала отдельно выполните `supabase/migrations/20260924010000_kazakh_locale.sql`, затем повторите импорт.

Килограммовые пачки Pro Barista — отдельные товары от уже имеющихся пачек 250 г. Названия, цены и вес последних не меняются.

Длинные описания сокращены до одного-двух предложений. Вкусовые ноты вынесены в поле букета, фактические сведения — в характеристики. Классификация по существующим фильтрам: линейка Profile — `profiles`, декофеинизированный кофе — `decaf`, остальные лоты — `microlot`. Эту классификацию можно уточнить в кабинете.

## Как работает группировка и защита от повторов

Используется существующее поле `products.sort_order`, схема и интерфейс не меняются. Выбранные 20 позиций размещаются после остальных товаров единым блоком, в порядке групп из таблицы. Остальные товары не переставляются; вся ранее существовавшая линейка бренда вне этих 20 не перегруппировывается.

В публичном каталоге порядок применяется по мере публикации. В staff-панели фильтры и сортировка по статусу могут разделять группы. Сортировка по названию всегда алфавитная.

Обжарщик записывается обычной характеристикой **«Обжарщик»**. Поле `products.brand` не используется: сейчас оно допускает только бренды оборудования.

Перед вставкой проверяются slug и совпадения названия/фасовки. Если найдена существующая карточка, **её цена, тексты, фото, существующие переводы и публикация сохраняются**; добавляются отсутствующие локали и меняется порядок. Поэтому уже существующую карточку с устаревшими данными при необходимости исправьте через кабинет. Повторный запуск сохраняет правки и фотографии, добавленные после импорта.

Если найдены несколько возможных совпадений или две импортируемые позиции сопоставлены одному товару, скрипт останавливает всю транзакцию. Он не выбирает произвольную карточку. Не удаляйте товары для обхода этой ошибки — сначала уточните совпадение.

Неизвестная фасовка не считается другой фасовкой: при совпадении названия скрипт сохраняет существующий товар. Совершенно другое название и slug могут скрыть дубликат — автоматическая проверка не определяет смысл всех возможных переименований.

## Что уточнить по исходникам

- **Руанда Кабуе / Колумбия Джеферсон Кастаньо:** бренд не виден, характеристика обжарщика не добавлена.
- **Дрип-кофе Miriam Pink Bourbon:** цены нет на скриншоте, цена оставлена пустой, не `0` и не предполагаемые `2400`.
- **Serikov:** вес упаковок не указан читаемо, фасовка оставлена пустой.
- **Ethiopia Elto Sama:** текст карточки описывает Elto Sama, но на фото видны другие лоты Hypno — Sama Honey и Mesele. Бренд определён по этому фото; проверьте его. Фасовка не перенесена с соседних упаковок.
- **Дрипы Massimo:** не видно числа порций и веса. Цена `2400` перенесена как цена товара из карточки без утверждения, что это цена за один пакет или коробку.
- **Daannisa / Shakisso:** в описаниях оценка `88`, на этикетках `87+`. Использовано значение из текста; проверьте перед публикацией.
- **Brazilian Profile 1.0:** в описании букета карамель, на этикетке чернослив. Использован текст карточки. Обработка и разновидность прочитаны с этикетки.
- Обжарка у Massimo не указана в текстах этих карточек и не добавлена по предположению.

После изменения публичных данных напрямую через SQL кэш сайта может обновляться до пяти минут. Обновление карточки через кабинет использует штатное обновление кэша.
